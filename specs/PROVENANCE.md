## Why there are two digests

**The raw sha256 is not a drift signal.** Google's Discovery service serializes JSON
object keys in a non-deterministic order, so two fetches of an identical document
produce different bytes and different sha256 values. On 2026-09-16 the Calendar
document came back with a different raw sha256 and the *same* byte count, same
revision, and semantically identical content - the key order had simply been
reshuffled. Comparing raw digests would have reported drift where there was none.

The **canonical sha256** is the digest of the document re-serialized with sorted keys
and no insignificant whitespace. It is stable across fetches and is the digest to
compare when answering "has this changed":

```bash
python3 -c "import json,hashlib,sys;print(hashlib.sha256(json.dumps(json.load(open(sys.argv[1])),sort_keys=True,separators=(',',':')).encode()).hexdigest())" specs/gmail-v1-discovery.json
```

The raw sha256 stays recorded because it identifies the exact bytes committed here.
